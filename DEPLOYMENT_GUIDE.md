## ⚡ Surge.sh Hosting Architecture

Surge.sh is a high-speed, zero-maintenance static web publishing service designed specifically for modern client-side Single-Page Applications (SPAs).

### Deployment Specifications

| Parameter | Configuration | Purpose & Implementation |
| :--- | :--- | :--- |
| **Domain** | `lifetools.surge.sh` | Defined in `public/CNAME` and verified in `dist/CNAME` |
| **Publish Directory** | `./dist` | Contains compiled HTML, bundled JS chunks, CSS, and static assets |
| **SPA Fallback** | `dist/200.html` | Automatically cloned from `dist/index.html` via `scripts/prepare-surge.cjs` |
| **Build Command** | `npm run build` | Runs `tsc -b`, `vite build`, `generate-sitemap.cjs`, and `prepare-surge.cjs` |
| **Deploy Command** | `npm run deploy` | Runs `npm run build && surge ./dist publish` |
| **Sitemap** | `dist/sitemap.xml` | Generated with 684 URLs for indexing across all 633 tools |

## 🔄 SPA Client-Side Routing on Surge.sh (`200.html`)

LifeTools uses client-side routing with hash and direct deep-link paths (e.g. `https://lifetools.surge.sh/#/tool/url-qr-generator`, `https://lifetools.surge.sh/#/workspace`, `https://lifetools.surge.sh/#/categories/home`).

### How Surge Handles SPAs
- When a user visits a direct URL or refreshes a browser tab on a deep route, traditional servers look for a matching folder or file and return HTTP 404 if not found.
- Surge.sh natively solves this by searching for **`200.html`** in the project root.
- When `200.html` is present, Surge serves it with an **HTTP 200 OK** status code (not 404).
- The browser downloads the application bundle, React mounts cleanly, and the client-side router loads the target route without interruption.

### Automated Generation via Post-Build Script
LifeTools includes `scripts/prepare-surge.cjs`, which runs automatically on every `npm run build`:
1. Verifies that `dist/index.html` was generated by Vite.
2. Clones `dist/index.html` to `dist/200.html`.
3. Verifies that `dist/CNAME` contains `lifetools.surge.sh`.
4. Checks `dist/sitemap.xml` size and integrity.

## 🚀 How to Authenticate and Deploy

Follow these steps to deploy LifeTools to Surge.sh:

### Step 1: Ensure Dependencies are Installed
Open your terminal in the project directory:
```bash
npm install
```

### Step 2: Authenticate with Surge (One-Time Setup)
If you are deploying from a machine that has not logged into Surge before, authenticate with your Surge account:
```bash
npx surge login
```
*You will be prompted to enter your email and choose a password or authenticate your token.*

To check which Surge account is currently active:
```bash
npx surge whoami
```

### Step 3: Run the Production Deployment Command
Run the single unified deployment script configured in `package.json`:
```bash
npm run deploy
```

This command executes:
```bash
npm run build && surge ./dist publish
```

Surge reads `./dist/CNAME`, identifies the target domain as `lifetools.surge.sh`, uploads `./dist`, and publishes the site with HTTPS enabled automatically!

## 🛠️ Alternative Manual Commands

If you prefer to build and deploy in separate steps:

```bash
# 1. Compile TypeScript and bundle production assets
npm run build

# 2. Deploy the dist folder to the configured CNAME
npx surge ./dist publish
```

Or deploy explicitly to the domain:
```bash
npx surge ./dist lifetools.surge.sh
```

## 🔍 Post-Deployment Verification Checklist

Once Surge finishes publishing:

1. **Verify Root URL:**
   - Open `https://lifetools.surge.sh/`
   - Check that the hero section, monogram logo, categories dropdown, and search bar render instantly.
2. **Verify SPA Refresh on Nested Routes:**
   - Navigate to `https://lifetools.surge.sh/#/tool/url-qr-generator`
   - Press **F5** / **Ctrl+R** to reload the page.
   - Confirm the page reloads cleanly with zero 404 errors.
3. **Verify Custom Logo QR Generator:**
   - Upload a test logo, toggle shapes (Circle, Rounded Square, Square), customize colors and padding.
   - Confirm real-time jsQR validation badge is green and downloads (PNG, 2048px, SVG) succeed.
4. **Verify Offline / PWA Support:**
   - Open Developer Tools > Application > Service Workers.
   - Confirm `sw.js` is registered and active.
5. **Verify Sitemap & Robots:**
   - Open `https://lifetools.surge.sh/robots.txt`
   - Open `https://lifetools.surge.sh/sitemap.xml`
